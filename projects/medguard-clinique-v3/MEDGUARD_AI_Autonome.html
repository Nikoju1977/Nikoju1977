INTÉGRATION SERVEUR

Un garde-fou entre votre IA et son utilisateur.

Le même moteur existe sous forme d'API FastAPI. Connectez-le aux réponses produites par un agent ou un système de génération augmentée par documents (RAG).

POST/api/v3/check

Le mode API V3 exige une référence inscrite dans un registre de confiance administré, avec empreinte SHA-256 correspondante et période de validité. Le registre livré est vide : toutes les requêtes sont bloquées par défaut. Le navigateur fonctionne seulement en mode laboratoire à sources déclaratives. Réponse possible : BLOCKED si une affirmation est non étayée ou un identifiant détecté ; HUMAN_REVIEW si toutes les phrases correspondent exactement à des sources déclarées revues. Il n'existe pas de statut d'autorisation clinique automatique.

La vérification côté navigateur est locale ; pour un déploiement multiutilisateur, faites appliquer le blocage côté serveur, avec contrôle d'accès et audit sécurisé.
EXEMPLE DE REQUÊTE
curl -X POST http://127.0.0.1:8000/api/v3/check \
  -H 'X-API-Key: VOTRE_CLE_API_LOCALE' \
  -H 'Content-Type: application/json' \
  -d '{
    "answer": "Le matériel fictif doit être contrôlé.",
    "sources": [{
      "id": "ref-1",
      "title": "Exemple synthétique",
      "version": "1.0",
      "reviewer": "Relecteur déclaré",

MODÈLE DE CONFIANCE

Ce que le système fait et ne fait pas.

01 / Correspondance exacte

Vérifie si chaque phrase normalisée est identique à une phrase dans une source déclarée revue. Une simple ressemblance n'est jamais suffisante.

02 / Blocage par défaut

La moindre phrase non étayée, donnée personnelle détectée ou absence de preuve bloque la sortie. Les variations de nombres et de négation ne sont pas autorisées.

03 / Audit explicite

Fournit une décision, les extraits de preuves et les empreintes SHA-256 quand l'environnement le permet. Un humain qualifié doit confirmer la pertinence clinique.

Limites fondamentales

  • Une source peut être fausse, périmée ou non applicable au patient.
  • Une phrase littéralement copiée peut être sortie de son contexte.
  • Un raisonnement faux peut utiliser des phrases exactes.
  • Les omissions, contradictions complexes, recommandations personnalisées et données sensibles non détectées restent possibles.
  • Les déclarations de relecture et liens source ne sont pas authentifiés.
  • Ce logiciel n’est pas certifié dispositif médical et n’a pas subi de validation clinique ; aucune affirmation de conformité RGPD n’est portée.

Avant tout usage médical réel : revue de risques, validation sur jeux de cas cliniques, gouvernance des sources, sécurité RGPD, supervision humaine et analyse réglementaire MDR/AI Act adaptées à l'usage envisagé.

DONNÉES & SÉCURITÉ

Politique de démonstration

Aucun compte, aucun cloud, aucune analytique

Le moteur web traite le texte dans la mémoire du navigateur. Le code ne l’envoie à aucun service distant.

Pas de registre patient

Aucune donnée patient réelle ne doit être saisie. Les détecteurs d’identifiants restent partiels : ils ne garantissent pas l’anonymat.

Effacement volontaire

Utilisez « Tout effacer » dans Vérification puis fermez la page. Un navigateur ou appareil peut conserver des traces hors du contrôle de cette application.

API de développement protégée

Exclusivement en boucle locale, clé secrète obligatoire, refus des origines web extérieures. Aucun serveur cloud ou hébergement HDS n’est livré.

Usage professionnel restant à qualifier

Pour des données de santé personnelles ou une utilisation clinique, réaliser l’AIPD selon les risques, examiner le besoin HDS et obtenir les évaluations réglementaires adaptées.
